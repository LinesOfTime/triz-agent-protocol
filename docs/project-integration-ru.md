# Интеграция в проект

Минимальная интеграция состоит из инструкции агенту, компактного состояния и точечного поиска зависимостей. Не требуется помещать всю историю проекта в постоянный контекст.

Пример для `AGENTS.md`:

```markdown
При конфликтующих требованиях, повторяющейся регрессии или архитектурном компромиссе используй навык `triz-problem-solving`.

Начинай с текущей задачи, этого файла, компактного состояния проекта и непосредственно затронутых файлов. Расширяй контекст по найденным сущностям и недостающим доказательствам. Историю читай только при конфликте или отсутствии актуального объяснения.

Отделяй факты от предположений. Сохраняй инварианты и пользовательские данные. Для каждого варианта указывай риск, опровергающую проверку и минимальный обратимый следующий шаг.
```

Рекомендуемая иерархия источников: текущая задача → `AGENTS.md` → компактное состояние → принятые решения → актуальная документация → история. Локальные правила проекта имеют приоритет над общим протоколом.

Протокол стоит включать по сигналам сложности, а не для каждой правки: конфликт требований, неизвестная причина повторяющегося сбоя, несколько механизмов с разными потерями или высокая цена необратимого решения.
