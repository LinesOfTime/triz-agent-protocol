# Сравнительная оценка протокола

Цель эксперимента — измерить различие результатов при одинаковой модели и задаче, а не заранее подтвердить полезность протокола.

## Условия парного прогона

- Используется одна точная версия модели.
- Совпадают параметры декодирования, инструменты и доступные исходные свидетельства.
- Отличается только наличие TRIZ Agent Protocol в условии `protocol`.
- Порядок baseline/protocol чередуется между повторениями.
- Каждый новый сеанс не получает ответ из другого условия.
- `gold.json` недоступен модели до фиксации результата.
- Неудачные и нулевые результаты сохраняются наряду с успешными.

Для каждого каталога результатов обязателен `run.json`. Он связывает парные прогоны и фиксирует модель, версию, настройки и политику контекста. Поле `simulation: true` запрещает трактовать демонстрационные данные как реальный эксперимент.

## Измеряемые свойства

- полнота найденных критических элементов;
- точность перечня критических элементов;
- число неподтверждённых утверждений;
- число нарушенных или неучтённых инвариантов;
- доля кейсов, удовлетворивших структурным критериям PASS.

Эти метрики не измеряют новизну решения, практическую ценность или соответствие классической ТРИЗ. Для таких выводов нужны отдельная рубрика и независимые рецензенты.

## Команды

```bash
triz benchmark-suite benchmarks/suite-v1/suite.json results/baseline --output baseline-score.json
triz benchmark-suite benchmarks/suite-v1/suite.json results/protocol --output protocol-score.json
triz compare baseline-score.json protocol-score.json --output comparison.json
```

Положительная дельта recall, precision и pass rate означает улучшение. Для неподтверждённых утверждений и нарушений инвариантов улучшением является отрицательная дельта. Само наличие дельты не устанавливает статистическую значимость.
